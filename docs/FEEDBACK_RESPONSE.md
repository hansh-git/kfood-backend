# 피드백 반영 정리 (백엔드 · 김현수)

| 피드백 | 담당 | 반영 내용 |
|---|---|---|
| 사용 시나리오 설정 | 기획(남태욱) 주도 | 아래 백엔드 기준 시나리오 3개 제공 → 계획서에 활용 |
| 구현 기능 상세 정리 | 전원 | 백엔드 기능은 `docs/API.md`로 정리 |
| 음식 성분 퍼센테이지 | 김현수 | `/analyze` 재료별 `ratio_percent`(AI 추정, 합계 100으로 정규화) + 추정치 고지 문구 |
| 유사 앱 차이점 | 기획 주도 | 백엔드 차별점 근거: ① LLM이 아닌 규칙 기반 판정(재현성·테스트 가능) ② 필수/변형 재료 구분 + 직원 확인 루프 |
| ① 프로필을 종업원에게 보여주는 방법 | 김현수(API) · 김유경(화면) | `GET /profile/card` — 고정 템플릿 한국어 카드(오역 없음), 전체화면·TTS 읽기 |
| ② 주재료가 다른 메뉴(짬뽕 등) | 김현수(파이프라인) · 한석호(DB) · 유동민(화면) | 메뉴 기준 DB(필수/숨은/변형 재료) → 필수 재료 위험도 먼저(WARNING) → 변형 재료는 CAUTION + 직원 질문 → TTS 질문·STT 답변 → `/qna/confirm`으로 재판정 |

## 사용 시나리오 (백엔드 동작 기준)

**S1. 새우 알레르기(심각) 관광객이 중국집에서 '짬뽕' 주문 고민**
1. 메뉴판 촬영 → `/ocr` → 짬뽕·짜장면·탕수육 추출
2. `/analyze` → 짬뽕: 필수 재료(면) 문제 없음, 해물짬뽕 변형에 새우 가능 → **CAUTION**
3. 화면에 "짬뽕에 새우가 들어가나요?"(한국어) + 영어 번역, 스피커 버튼으로 TTS 재생
4. 사장님 "해물 들어가요" 음성 → `/stt` → `/qna/confirm` → **WARNING**으로 갱신 → 짜장면 추천 확인

**S2. 할랄 식단 관광객이 국밥집 방문**
1. `/analyze` → 돼지국밥: 필수 재료 돼지고기 → 질문 없이 즉시 **WARNING**
2. 프로필 카드 버튼 → `/profile/card` 한국어 카드를 직원에게 보여주고 먹을 수 있는 메뉴 문의

**S3. 비건 관광객이 칼국수집 방문**
1. `/analyze` → 칼국수: 멸치 육수 가능 → **CAUTION**, "칼국수에 멸치 육수가 들어가나요?"
2. 직원이 [아니요] 버튼 → `/qna/confirm` → **SAFE**
3. "Is it spicy?" → `/qna`로 추가 질문
